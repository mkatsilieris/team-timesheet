# Team Timesheet

Μικρή web εφαρμογή για την καταγραφή των ωρών που δουλεύει κάθε μέλος της ομάδας ανά ημέρα και project. Τρέχει σε ένα Docker container και σερβίρεται στην πόρτα 9999.

## Εκκίνηση στο VM

```bash
docker compose up -d --build
```

Η εφαρμογή ανοίγει στο `https://<ip-του-vm>:9443`. Η παλιά διεύθυνση `http://<ip-του-vm>:9999` κάνει redirect εκεί. Τα δεδομένα αποθηκεύονται στο `./data/timesheet.db` (SQLite). Ο φάκελος είναι volume του container, οπότε τα δεδομένα δεν χάνονται όταν ξαναχτίζεται το image.

Χρήσιμες εντολές:

```bash
docker compose logs -f            # logs
docker compose up -d --build      # νέα έκδοση μετά από αλλαγές στον κώδικα
docker compose down               # σταμάτημα (τα δεδομένα μένουν στο ./data)
```

Αν το VM έχει firewall, πρέπει να ανοίξουν οι πόρτες 9443 και 9999 (π.χ. `sudo ufw allow 9443/tcp`, ή NSG rule αν το VM είναι στο Azure).

## HTTPS

Μπροστά από την εφαρμογή τρέχει ένα Caddy (`Caddyfile`), που σερβίρει HTTPS στην πόρτα 9443. Η ίδια η εφαρμογή δεν ακούει σε καμία πόρτα του host. Τα ονόματα ή IP για τα οποία εκδίδεται το πιστοποιητικό ορίζονται στο `TLS_HOSTS` του `.env`.

Το πιστοποιητικό το εκδίδει μια τοπική CA του Caddy, οπότε την πρώτη φορά ο browser δείχνει προειδοποίηση. Για να φύγει, εγκαταστήστε το root πιστοποιητικό της CA στους υπολογιστές των χρηστών:

```bash
docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt ./timesheet-root.crt
```

Στα Windows: διπλό κλικ στο `timesheet-root.crt` → «Εγκατάσταση πιστοποιητικού» → «Τρέχων χρήστης» → «Αξιόπιστες κεντρικές αρχές έκδοσης πιστοποιητικών». Η CA μένει στο volume `caddy_data`· αν σβηστεί το volume, φτιάχνεται νέα και το βήμα πρέπει να γίνει ξανά.

Όταν υπάρξει DNS όνομα και πιστοποιητικό από την εταιρική CA, αλλάζει μόνο η γραμμή `tls internal` στο `Caddyfile` (π.χ. `tls /certs/cert.pem /certs/key.pem`, με τα αρχεία σε volume).

## Μεταφορά δεδομένων από την έκδοση με το Excel στο OneDrive

Αντιγράψτε το `Timesheet_DB.xlsx` στον φάκελο `data/` **πριν** από την πρώτη εκκίνηση. Όταν η βάση είναι άδεια, η εφαρμογή εισάγει από αυτό το αρχείο την ομάδα, τα projects, τις ώρες και το ιστορικό. Αν το αρχείο δεν υπάρχει, η εφαρμογή ξεκινά με την ομάδα και τα projects που ορίζονται στο `app/db.py`.

Αν η βάση έχει ήδη δημιουργηθεί, σβήστε το `data/timesheet.db` και ξανατρέξτε το container για να γίνει η εισαγωγή.

## Χρήστες και πρόσβαση

- Η εγγραφή γίνεται μόνο με εταιρικό email (`@netcompany.com`). Ο χρήστης λαμβάνει με email έναν κωδικό πρόσβασης, που ισχύει μέχρι να τον αλλάξει ο ίδιος από την επιλογή «Αλλαγή κωδικού».
- Ένας νέος χρήστης ξεκινά «Σε αναμονή» και βλέπει μόνο μια σελίδα που λέει ότι η πρόσβασή του περιμένει έγκριση. Ένας διαχειριστής του δίνει πρόσβαση από την καρτέλα «Χρήστες».
- Τα emails της μεταβλητής `ADMIN_EMAILS` γίνονται διαχειριστές αυτόματα, οπότε έτσι ορίζεται ο πρώτος διαχειριστής.
- Με «Ξέχασα τον κωδικό» στέλνεται νέος κωδικός. Ο παλιός ισχύει μέχρι να χρησιμοποιηθεί ο νέος.
- Οι κωδικοί αποθηκεύονται μόνο ως scrypt hash. Μετά από 10 λάθος προσπάθειες ο λογαριασμός κλειδώνει για 15 λεπτά.
- Οι ρυθμίσεις (SMTP, διαχειριστές) μπαίνουν σε ένα αρχείο `.env` δίπλα στο `docker-compose.yml`· δείτε το `.env.example`. Χωρίς `SMTP_HOST` ο κωδικός δεν στέλνεται αλλά γράφεται στα logs (`docker compose logs`), για τοπικό τεστ.

## Τι κάνει

- **Ώρες:** επιλέγετε άτομο και μήνα. Οι ημερομηνίες είναι γραμμές και τα projects στήλες. Η εφαρμογή αποθηκεύει κάθε αλλαγή αυτόματα μετά από ένα δευτερόλεπτο.
- **Σύνοψη:** δείχνει ώρες ή man-days ανά άτομο και project για όποιο διάστημα επιλέξετε.
- **Ομάδα & Projects:** προσθέτετε άτομα και projects, και απενεργοποιείτε όσα δεν χρειάζονται πια.
- **Ιστορικό αλλαγών:** η εφαρμογή γράφει κάθε αλλαγή μαζί με το ποιος την έκανε, πότε, και την παλιά και τη νέα τιμή. Το ιστορικό δεν σβήνεται.
- **Λήψη Excel:** κατεβάζει ένα αρχείο με σύνοψη, ένα sheet ανά άτομο (ημερομηνίες × projects), τα πρωτογενή δεδομένα, τα μηνιαία σύνολα και το ιστορικό.

Αν δύο χρήστες αλλάξουν την ίδια τιμή σχεδόν ταυτόχρονα, η εφαρμογή κρατά τη νεότερη αλλαγή και σημειώνει τη σύγκρουση στο ιστορικό.

## API

| Method | Path | Περιγραφή |
|---|---|---|
| POST | `/api/auth/register` | Εγγραφή `{email, name}`· ο κωδικός πρόσβασης στέλνεται στο email |
| POST | `/api/auth/login` | Είσοδος `{email, password}`· βάζει το cookie `ts_session` |
| POST | `/api/auth/forgot` | Νέος κωδικός στο email `{email}` |
| POST | `/api/auth/password` | Αλλαγή κωδικού `{current, new}` |
| GET | `/api/auth/me` · POST `/api/auth/logout` | Τρέχων χρήστης · αποσύνδεση |
| GET | `/api/admin/users` | Λίστα χρηστών (μόνο διαχειριστές) |
| POST | `/api/admin/users/role` | Αλλαγή ρόλου `{email, role: pending\|user\|admin}` (μόνο διαχειριστές) |
| GET | `/api/state` | Ομάδα, projects, όλες οι καταχωρίσεις και το version |
| GET | `/api/version` | Μετρητής που αυξάνει σε κάθε εγγραφή (το UI κάνει polling κάθε 30″) |
| POST | `/api/changes` | Δέσμη αλλαγών `{user, entries[], team[], projects[]}` |
| GET | `/api/log?limit=` | Ιστορικό, τα νεότερα πρώτα |
| GET | `/api/export?from=YYYY-MM-DD&to=YYYY-MM-DD` | Excel για download |
| GET | `/api/backup` | Αντίγραφο της SQLite βάσης |
| GET | `/healthz` | Health check |

## Τοπικό development

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows (Linux/macOS: source .venv/bin/activate)
pip install -r requirements-dev.txt
set DATA_DIR=./data               # Windows cmd (PowerShell: $env:DATA_DIR="./data")
uvicorn app.main:app --reload --port 9999
pytest
```

## Δομή

```
app/main.py             FastAPI: API και σερβίρισμα του UI
app/auth.py             Εγγραφή, είσοδος, κωδικοί, sessions, ρόλοι και αποστολή email
app/db.py               Σχήμα SQLite, αρχικά δεδομένα, συναλλαγές εγγραφής
app/export.py           Παραγωγή του Excel για download (openpyxl)
app/importer.py         Εισαγωγή του Timesheet_DB.xlsx της προηγούμενης έκδοσης
app/static/index.html   Ολόκληρο το UI (vanilla JS, χωρίς build step)
tests/                  Tests του API και του auth
```

## Περιορισμοί

- Το ιστορικό καταγράφει το ονοματεπώνυμο που έδωσε ο χρήστης στην εγγραφή.
- Το πιστοποιητικό HTTPS είναι από την τοπική CA του Caddy, όχι από την εταιρική· δείτε την ενότητα HTTPS. Αν το VM είναι προσβάσιμο έξω από το εσωτερικό δίκτυο, χρειάζεται reverse proxy με HTTPS.
- Η εφαρμογή τρέχει με έναν uvicorn worker, γιατί η SQLite δέχεται έναν writer τη φορά. Για μια ομάδα αυτό αρκεί.
- Κάντε backup τον φάκελο `data/` ή καλείτε περιοδικά το `/api/backup`.
